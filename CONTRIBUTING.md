# Участие в разработке

## Требования

- [Bun](https://bun.sh) 1.3.14 или выше. Node.js не используется: все операции — через `bun` (`bun install`, `bun add`, `bun remove`).

```bash
bun install
cp .env.example .env   # впишите TELEGRAM_BOT_TOKEN
bun run dev
```

Шага сборки нет — бот запускается прямо из TypeScript.

## Скрипты

| Команда | Что делает |
| --- | --- |
| `bun run dev` | Запуск с автоперезапуском при изменениях |
| `bun run start` | Обычный запуск |
| `bun test` | Тесты. Покрытие включено по умолчанию в `bunfig.toml` |
| `bun run test:coverage` | Тесты с явным отчётом о покрытии |
| `bun run lint` | ESLint |
| `bun run lint:fix` | ESLint с автоисправлением |
| `bun run format` | Prettier |
| `bun run format:check` | Проверка форматирования без изменений |

## Перед отправкой pull request

```bash
bun run lint && bun run format:check && bun test
```

Те же три проверки выполняет CI ([`.github/workflows/ci.yml`](.github/workflows/ci.yml)).

## Правила, о которых легко забыть

**Все строки, которые видит пользователь, — на русском.** Это русскоязычный бот; английский текст в ответах, описаниях команд и сообщениях об ошибках недопустим. Комментарии в коде и внутренняя документация — на английском.

**Экземпляр бота — синглтон.** [`src/config/bot.ts`](src/config/bot.ts) экспортирует единственный `bot`. Его **нельзя** передавать в функции параметром: импортируйте напрямую там, где он нужен.

**[`src/commands/definitions.ts`](src/commands/definitions.ts) — единственный источник правды для команд.** Этот файл одновременно наполняет меню бота в Telegram, вывод `/help` и регистрацию обработчиков. Команда, добавленная в обход него, не появится нигде из трёх мест. Порядок добавления описан в скилле [`.claude/skills/add-bot-command`](.claude/skills/add-bot-command/SKILL.md):

1. Создайте `src/commands/<имя>.ts` с функцией `register<Имя>Command()`.
2. Добавьте запись `{ command, description, helpText, register }` в `definitions.ts`.
3. Импортируйте туда же функцию регистрации.

**Настройки канала — это JSON-блоб.** Новое поле добавляется в интерфейс `ChannelSettingsData` в [`src/db/database.ts`](src/db/database.ts) и не требует миграции схемы. Так задумано.

**События телеметрии объявляются только в `TelemetryEventProperties`** в [`src/telemetry/events.ts`](src/telemetry/events.ts) — иначе код не пройдёт проверку типов. Порядок описан в скилле [`.claude/skills/add-telemetry-event`](.claude/skills/add-telemetry-event/SKILL.md). Две вещи, которые важно не сломать:

- **Не добавляйте свойство, способное содержать текст пользователя.** Отправляйте длину, количество или флаг. Данные о людях (Telegram ID, `@username`, имена) не отправляются в открытом виде — только хеш из [`src/telemetry/identity.ts`](src/telemetry/identity.ts). Данные о каналах (ID и название), наоборот, отправляются как есть: канал публичен. Что именно уходит, описано в разделе «Телеметрия» в [README.md](README.md).
- **`captureEvent` не должна выбрасывать исключения и её не нужно `await`-ить.** Часть вызовов находится внутри `try`, чей `catch` сообщает пользователю о неудачной публикации, а часть — внутри таймера сборки альбомов, где исключение уронит процесс.

## Стиль кода

Форматирование задаёт Prettier (`.prettierrc`): отступ 4 пробела, ширина строки 120, двойные кавычки, висячие запятые. Запускайте `bun run format` перед коммитом.

Комментарии пишутся только там, где код сам себя не объясняет: обходные решения, неочевидная бизнес-логика, важные соображения безопасности или производительности. Комментарии, пересказывающие соседнюю строку (`// Получаем ID пользователя` над `const userId = ...`), не нужны.

## Тесты

Тесты лежат в `tests/` и запускаются через `bun test`. Логика проверки маркировки сосредоточена в [`src/handlers/message-helpers.ts`](src/handlers/message-helpers.ts) и покрыта `tests/message-helpers.test.ts` — изменения в ней обязательно сопровождайте тестами: это та часть, ошибка в которой пропускает немаркированный материал в канал.
